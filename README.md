# Crossplane

GitOps-managed installation of Crossplane for a personal homelab platform cluster.

Crossplane runs on a dedicated Kubernetes control-plane cluster and is used to manage infrastructure outside the cluster, initially the Proxmox environment.

> [!IMPORTANT]
> This repository is intended for **personal homelab use only**.
>
> The configuration is not designed, reviewed, or hardened for production environments.

## Architecture

Argo CD manages both the Crossplane runtime and the providers installed into Crossplane.

```text
GitHub
  │
  ▼
Argo CD
  │
  ├── Crossplane
  │
  └── Providers
  │       │
  │       └── Proxmox Provider
  │               │
  │               ▼
  │            Proxmox
  │
  └── External Secrets
          │
          ▼
      1Password
```

The Kubernetes cluster itself acts as a dedicated platform/control-plane cluster.

The intention is to keep normal workloads off this cluster and use it to manage infrastructure and other Kubernetes clusters.

## Argo CD

### Crossplane

`argocd/application.yaml` installs Crossplane from the official Crossplane Helm repository.

Crossplane is installed into:

```text
crossplane-system
```

### Providers

`argocd/providers.yaml` manages the provider configuration stored under:

```text
providers/proxmox
```

This keeps the Crossplane runtime lifecycle separate from the providers using it.

## Proxmox Provider

The initial provider allows Crossplane to interact with the Proxmox homelab environment.

The provider configuration consists of:

```text
providers/proxmox/
├── provider.yaml
├── providerconfig.yaml
├── externalsecret.yaml
└── kustomization.yaml
```

### `provider.yaml`

Installs the Crossplane Proxmox provider package.

### `providerconfig.yaml`

Configures the provider and references the credentials generated by External Secrets.

### `externalsecret.yaml`

Retrieves the Proxmox endpoint and API credentials from 1Password using External Secrets Operator.

### `kustomization.yaml`

Groups the Proxmox provider resources for deployment through Argo CD.

## Secrets

Secrets are not stored in Git.

The cluster uses External Secrets Operator with 1Password.

```text
1Password
    │
    ▼
External Secrets Operator
    │
    ▼
proxmox-credentials
    │
    ▼
Crossplane ProviderConfig
    │
    ▼
Proxmox Provider
```

The Proxmox `ExternalSecret` expects a 1Password item named:

```text
proxmox
```

with fields:

```text
url
password
```

The External Secrets references use the 1Password SDK provider syntax:

```text
proxmox/url
proxmox/password
```

The resulting Kubernetes Secret is created as:

```text
Namespace: crossplane-system
Name:      proxmox-credentials
```

and contains a `credentials` key with the provider configuration.

No credentials or API tokens should ever be committed to this repository.

## Bootstrap

Crossplane must already be managed by Argo CD before installing providers.

Apply the Crossplane Argo CD application:

```bash
kubectl apply -f argocd/application.yaml
```

Verify:

```bash
kubectl -n argocd get application crossplane
```

Expected state:

```text
NAME         SYNC STATUS   HEALTH STATUS
crossplane   Synced        Healthy
```

Once Crossplane is healthy, install the provider application:

```bash
kubectl apply -f argocd/providers.yaml
```

Argo CD will then reconcile the resources under:

```text
providers/proxmox
```

## Verification

Check all Argo CD applications:

```bash
kubectl -n argocd get applications
```

Check Crossplane:

```bash
kubectl -n crossplane-system get pods
```

Check installed providers:

```bash
kubectl get providers.pkg.crossplane.io
```

Check provider revisions:

```bash
kubectl get providerrevisions.pkg.crossplane.io
```

Check the ExternalSecret:

```bash
kubectl -n crossplane-system get externalsecret proxmox-credentials
```

Expected state:

```text
STATUS         READY
SecretSynced   True
```

Verify that the generated Secret exists:

```bash
kubectl -n crossplane-system get secret proxmox-credentials
```

Do not print or commit the contents of the credential Secret.

## GitOps Workflow

Changes should normally be made through Git rather than directly modifying managed resources in the cluster.

```text
Change
  │
  ▼
Git commit
  │
  ▼
GitHub
  │
  ▼
Argo CD
  │
  ▼
Crossplane
  │
  ▼
Proxmox
```

Argo CD is configured to automatically synchronize, prune removed resources, and self-heal configuration drift.

## Platform APIs

Crossplane XRDs, Compositions, Functions, and higher-level platform APIs can be developed separately from this repository.

The responsibility of this repository is primarily:

```text
Crossplane runtime
        +
Provider installation
        +
Provider credentials/configuration
```

Higher-level platform APIs can then consume these providers without coupling their lifecycle to the Crossplane installation itself.

## Goal

The long-term homelab architecture is:

```text
                    Git
                     │
                     ▼
                  Argo CD
                     │
                     ▼
             Platform Cluster
                     │
                Crossplane
                     │
          ┌──────────┴──────────┐
          │                     │
          ▼                     ▼
       Proxmox              Other APIs
          │
          ▼
  Kubernetes Clusters
          │
          ▼
     Applications
```

The platform cluster remains small and dedicated to managing the rest of the homelab infrastructure.
